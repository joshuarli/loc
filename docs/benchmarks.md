# Benchmarks

`make bench-list` lists names and areas. `make bench-check TIER=change WORKLOAD=count_generated_corpus` checks prerequisites and reports host readiness. `make bench` runs the Edit tier: driver selection tests. For a short Change run use `make bench TIER=change WORKLOAD=count_generated_corpus`; omit `WORKLOAD` to select all workloads, or use `AREA=walk`, `count`, or `render`, and `SKIP` for workload names. Multiple names can be separated by spaces. Unknown or empty selections fail. `DRY_RUN=1` prints commands without creating run files.

Change runs use two samples of one iteration, intended to exercise the workload and inspect its output, not establish a regression. Scenario uses ten samples of one iteration and does not compare against a baseline. Both tiers fail if the selected workload's report lacks the requested sample and iteration counts or a measured median. Full is manual only: `make bench TIER=full` invokes the original rustybench baseline command. Do not use Full as an automatic check. The first Change run builds the release benchmark and can take minutes; later runs are normally seconds per workload, depending on the host. A run writes individual logs and a summary under `.work/bench-runs/`; the summary lists excluded workloads and does not claim a performance verdict. Cargo rebuilds stale artifacts. The fixtures are tracked in the checkout, and the 800-file corpus is generated per invocation and cleaned up by the harness.

The harness measures timing and allocations in the Rust process; it does not check complete output, compare paired revisions, or include CLI startup and subprocess resource use. Use a separate interleaved comparison and host readiness checks for performance claims. macOS `sample` and Linux `perf` can attribute CPU; syscall and process-wide memory measurements require separate instrumented runs.
